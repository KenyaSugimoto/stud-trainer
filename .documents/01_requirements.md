# 要件定義書（Stud Trainer）

## 1. プロダクト概要
- プロダクト名: Stud Trainer
- 一言説明:
  - Studポーカーをプレイできるゲームアプリ
- ターゲットユーザー:
  - Stud Hi / Razz / Stud8 などのスタッド系ゲームをプレイ・学習したいプレイヤー
- 解決する課題:
  - プレイマネーでStudゲームを手軽に体験・練習するプラットフォームが少ない
- 想定プラットフォーム（Web / モバイル / PWA 等）:
  - Web（PC / スマホ対応、SPA）
  - 必要に応じて PWA 対応（オフライン利用強化）

## 2. スコープ

### 2.1 対象範囲
- ゲーム設定画面（GameSetupScreen）
  - プレイヤー数（2〜7人）の選択
  - ゲームタイプの選択（Stud Hi, Razz, Stud8）
  - 初期スタック額の入力
  - ゲーム開始ボタン
- ゲーム画面（GameScreen）
  - ポーカーテーブル(PokerStars風)の表示
    - テーブル背景（フェルト + リング）
    - 座席配置（7-maxの円形レイアウト）
    - 中央情報 & ベット/アンティ表示
    - ポット表示
  - 3rd〜7th のカード配布表示
  - bring-in プレイヤーを判定して、そのプレイヤーからアクション開始
  - 現在アクター（行動プレイヤー）の表示
  - 有効なアクションのみをボタンとして表示
    - アクションの種類: fold / call / bet / raise / bring-in / complete / check
  - アクション実行時のスタック変動・ポット更新
  - fold によるハンド終了
  - showdown による勝敗判定
  - 勝者決定後のチップ分配（単一ポット + Split 対応）
  - ハンド終了したら次のハンド開始ボタン表示
  - Next Hand 実行時にスタックを維持したまま新しいハンドを開始

### 2.2 非対象
- ログ / デバッグ用途
  - ストリートごとのアクションログを簡易表示
- ログイン / サインアップ / マルチユーザー管理
- オンライン対戦（リアルタイム通信）
- 本番運用を前提としたセキュリティ要件（JWT 等）
- 複雑なサイドポット計算
  - 初期バージョンでは「単一ポットのみ」をサポート
- 本格的なハンド履歴保存・集計・分析
  - 将来、ローカルストレージ or バックエンド導入で拡張

## 3. 必要な機能一覧

| 機能名                     | 簡易説明                                                                 |
|----------------------------|--------------------------------------------------------------------------|
| ゲーム初期化               | プレイヤー数・ゲームタイプ・初期スタックを入力し、新しいハンドを開始する |
| アンティ・ブリングイン処理 | アンティ徴収と、bring-in プレイヤーの自動判定                           |
| カード配布（3rd〜7th）     | ストリートごとのカード配布と UI への反映                                |
| アクション処理             | fold / call / bet / raise / complete などの適切なアクション処理         |
| アクター管理               | 現在のアクターの算出と、ターン終了後の次アクター決定                     |
| ポット管理                 | ベット額の集計、ポットへの反映                                          |
| 勝敗判定（ショーダウン）   | Stud Hi ルールでの役判定と、最良ハンド / Split Pot 判定                  |
| チップ分配                 | 勝者（または複数勝者）へのポット分配とスタック更新                      |
| ハンド終了フロー           | handFinished フラグ制御、勝者表示、Next Hand ボタン表示                 |
| 次ハンド開始               | スタックを維持したまま、新しいハンドを初期化                            |
| プレイヤー情報表示         | 各プレイヤーの名前 / スタック / ステータス / カード表示                  |

## 4. 非機能要件（簡易版）
- パフォーマンス
  - 単一ユーザーのローカル利用を想定
  - アクションに対して UI が即時に再描画されること
- セキュリティ
  - 初期バージョンでは外部 API やユーザー情報を扱わないため最小限
- 運用・保守
  - フロントエンド単体（静的ホスティング）で完結
  - バージョン管理は GitHub リポジトリで実施
- 拡張性
  - ロジックは `utils/*` に分離し、評価ロジックなどは単体テスト可能な構造にする
  - 将来の Razz / Stud8 対応を見据えてゲームタイプを enum で管理する

## 5. 制約
- 使用技術
  - React + TypeScript + Vite
  - Zustand（状態管理）
  - Tailwind CSS（スタイル）
- 個人開発であり、学習目的も含むため、過剰な設計は避ける
- UI はモバイルファーストだが、PC でも利用可能な程度のレスポンシブ対応
